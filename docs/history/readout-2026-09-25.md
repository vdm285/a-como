## 1. In one paragraph

**Comparador de Precios CDMX** is a one-page mobile web prototype (`index.html`, 43 KB, Tailwind + inline
JavaScript) that shows grocery prices for one hard-coded store (a Walmart
branch) and colours each price green or red against other products of the same kind,
per label price or per 100 g/ml. You can type a new product + price (optionally a photo) and
"update or report" an existing one. **Nothing is saved yet** (it all lives in memory until you
reload), there is no offline mode and no PWA files, and the location filter is a placeholder. A
separate Python script turns Walmart web pages you saved by hand into JSON product lists (run in
Google Colab). It is live, public, at https://vdm285.github.io/compa-precio/ (GitHub Pages, last
deployed 2026-03-29).

## 3. How it works today (as built)

### Screen
- **Header:** a postal code and a store name (both hard-coded text, `index.html:38,41`);
  image on/off button; menu button (shows an `alert`, `:50`); search box; two switches:
  *Etiqueta ↔ x100g/ml* and *Promedio ↔ Más barato*.
- **Cards** (one per record in the current store): category label, name without the size, brand,
  parsed size, big coloured price, source badge ("Web Scraping", "Actualizado por ti",
  "Competencia"), a comparison sentence ("33.1% debajo de la media") and an amber "report" button.
- **"+" button → "Registrar Producto":** photo (camera), name (required), label price (required).
  While you type the name it suggests a category.
- **Report button → "Actualizar o Reportar":** new price, new photo, "not found", correct the
  category (native `<datalist>`), free notes; "Solo Reportar" or "Confirmar Actualización".
- **Location modal:** "Solo esta Sucursal" (checked); "Mismo C.P." and "Toda la Ciudad" disabled.

### Engine (`procesarDatos`, `index.html:296-387`)
1. Find the first "number + unit" in the name (`ml|l|g|kg|litros|mililitros`, `:297`); convert
   kg→g and l→ml; price per 100 g or 100 ml = price ÷ size × 100. No unit → "u" and no per-100 price.
2. Category = first of 8 regexes that matches the name (`:257-266`).
3. The comparison group ("peras con peras") is the record's `subtipo` if it has one, otherwise the
   category name (`:327`).
4. Per group: count, sum, min, max of the per-100 price across **all** records (`:340-348`).
5. Colour: cheapest = dark green, dearest = dark red, below mean = green, above = red (`:358-384`).

### Data model
- **In the app:** one flat array `datosCrudos` (`:277`) of 8 mock records shaped like
  `{ id, nombre, precio: {actual}, marca, subtipo, tienda_id, url_foto, registro_meta: {timestamp, origen_id} }`.
  Product and price are fused (the README's own model separates them; see below).
- **In the README (the intended model):** `Producto {id_producto, nombre_raiz, marca, subtipo_calculo}`
  and `Registro_Precio {id_registro, timestamp, id_producto, id_tienda, precio_etiqueta,
  presentacion_parseada {valor, unidad}, registro_meta {origen_id, tiene_foto}}`. This is a sound
  event-log design (every price is a dated "ticket"; history is never overwritten).
- **Scraper output:** `{ nombre, tamano_porcion: "620 g", precio: {actual, anterior}, marca, tipo, subtipo }`.
  No id, no store, no date.

### Where data lives
Only in the page's memory. Reload = everything typed is gone. Photos are held as full-size
base64 text in memory. "Reports" are printed to the browser console (`:635`). No server, no
storage, no network calls except the two CDNs and the Unsplash mock photos.

## 4. What works
- The page loads (with network) and renders the mock data; both switches, search (name + brand),
  the image toggle and the bottom-sheet modals work as coded.
- Unit maths is right for clean names: `1.07 kg` → 1070 g, `1.5 l` → 1500 ml.
- Live category hint while typing; native `<datalist>` for categories (light, no library).
- The README's design thinking is strong and matches Victor's house philosophy: 5-second rule at
  the shelf, "is this better than Google Sheets?", event log instead of overwriting prices, postal
  code instead of GPS, AI only at development time.
- The scraper's size regex is better than the app's (uses word boundaries): "12 latas 355 ml" → 355 ml.

### Polish
- 🟡 `alert()` at `:50` and `:626` although the README's own rule 3 forbids it.
- 🟡 Price fields are `type="number"` without `min` (`:135,170`): 0 and negative prices accepted.
  `inputmode="decimal"` asks phones for the decimal keypad ([MDN, updated 2026-04-17](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inputmode)).
- 🟡 Name field listens to `onkeyup` (`:128`): paste, autofill and dictation don't update the hint. Use `input`.
- 🟡 Icon-only buttons have no labels (`:46,50,95,450`): screen readers announce nothing.
- 🟡 Brand defaults to "Desconocida" (`:557`), which then shows on cards and matches searches for "desc".
- 🟡 `h-screen` on `<body>` (`:25`): on iPhone Safari 100vh can be taller than the visible area; check that the "+" button is not under the toolbar (use `dvh`).
- 🟡 README: escaped Markdown from Google Docs; mentions `blueprint_scraping_workshop.md`, which is not in the repo; says "PWA" but there are no PWA files yet.
- 🟡 iPhone data: Safari deletes all site storage after 7 days of Safari use without a visit, unless the app is installed on the Home Screen ([WebKit, 2020-03-24](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/); confirmed by [MDN, 2026-01-05](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria), as cited in ListoLista's research). A months-long price history must be installable and exportable.

## 6. How it relates to ListoLista

**Same DNA.** Same owner, same principles (instant, no accounts, local data, zero running cost,
Spanish first), same shape (one HTML file on GitHub Pages), same origin today, same shopper and
same store trip. ListoLista answers "what do we need?"; compa-precio answers "is this a good price?".

**ListoLista is six months ahead in engineering** (its checkpoint 1 was rebuilt 2026-09-25), and
most of what compa-precio lacks already exists there, tested:

| compa-precio needs | Already in ListoLista (`design/checkpoint-1`) | Reuse |
|---|---|---|
| Category that doesn't match inside words (B1) | `src/aisles.js`: accent folding, whole words, plurals, typo guesses; 1,651-word Mexican dictionary `data/aisles-es-MX.txt`, 14 aisles; 68 tests | Replace the 8 regexes. Bonus: `aisleOf()` returns the matched dictionary **term** (e.g. "catsup"), which is exactly the missing `subtipo` (B2). Needs a small synonym list (ketchup → catsup). |
| Quantity parsing | `ListoAisles.stripQuantity()` (kg, kilo, g, gr, l, litro, ml, pieza, paquete, docena, lata, bolsa, caja; "1,5" → "1.5") | Extend into a `parseSize()` that *returns* the quantity, with multipacks. |
| Build + tests with nothing to install | `tools/build.py` (src/ → one `index.html`), `tests/run.sh` (macOS `jsc`) | Copy the pattern as-is. |
| Offline + installable | `sw.js`, two manifests, icons, `navigator.storage` notes | Copy and rename. |
| Local storage wrapper, export | `store` helper in `src/app.js` | Copy. |
| Sharing prices between two phones (later) | `src/sync.js` (end-to-end encrypted, key in the link) + Cloudflare relay + `src/merge.js` | Price records are append-only events, so merging is just "union by id". |

**Merge paths (draft; decision D1):**
- **A. Sister apps, shared parts (recommended now).** Rebuild compa-precio on ListoLista's
  skeleton, copying `aisles.js` + dictionary (note the source commit). Own address. Low risk, no
  impact on ListoLista's checkpoint 1.
- **B. "Precios" as an opt-in switch inside ListoLista (recommended target).** At the store, in
  aisle view, tap a small price chip on an item → type the price → it goes to a local price log
  for that store; the item then shows "last time $X" with a green/red dot. The list already knows
  the product and (with the planned per-store aisle order) the store, so capturing a price costs
  one tap + digits: the 5-second rule, met. Loaded only when switched on (pay for what you use).
- **C. Full merge now.** Not recommended: it would reopen ListoLista right before its phone test.

## 7. Research notes (dated)
- **PROFECO "Quién es Quién en los Precios" (QQP) is open data** with exactly the README's model:
  product, presentation, brand, category, price, **date recorded**, chain, store name, **address,
  state, municipality/alcaldía, latitude, longitude** ([QQP data dictionary, datos.profeco.gob.mx,
  accessed 2026-09-25](https://datos.profeco.gob.mx/diccionarioDatosQQP.php)). Files for 2024, 2025
  and 2026 (`QQP_2026.zip`, `QQP_2025.rar`) are on [datos.profeco.gob.mx, accessed 2026-09-25](https://datos.profeco.gob.mx/datos_abiertos/qqp.php);
  size and freshness not checked (download needs Victor's OK). PROFECO's new QQP site covers about
  3,000 products and filters by alcaldía ([PROFECO press release, 2025-03-04](https://www.gob.mx/profeco/prensa/profeco-lanza-nuevo-sitio-del-quien-es-quien-en-los-precios-consulta-en-tres-sencillos-pasos?idiom=es-MX)).
  → A legal, free "reference price" source for CDMX, instead of scraping Walmart. It could also
  seed the product catalogue and the `subtipo` list.
- **Postal-code "radius":** CP digits are not distances (first two digits = state; nearby numbers
  can be far apart). If real distance is ever needed, GeoNames publishes Mexican postal codes with
  latitude/longitude under CC BY 4.0 ([GeoNames postal code readme, accessed 2026-09-25](https://download.geonames.org/export/zip/readme.txt));
  coordinate accuracy varies (the file carries an accuracy code per row), and a GeoNames forum thread is titled as reporting errors in Mexican CP coordinates ([forum.geonames.org](https://forum.geonames.org/gforum/posts/list/742.page), undated, title only, not read).
  Simpler default: a "Mis tiendas" list (the 2-4 stores you actually visit), no geography.
- **Google Sheets as backend** (README plan): ListoLista's research found Apps Script can only be
  polled (no push) and caps simultaneous runs at about 30 ([tanaikech README, 2025-06-24](https://github.com/tanaikech/taking-advantage-of-Web-Apps-with-google-apps-script/blob/master/README.md);
  [Sheets API limits, updated 2026-09-03](https://developers.google.com/workspace/sheets/api/limits)).
  For a personal price log: keep data on the phone, offer "Export CSV / to Google Sheet".
